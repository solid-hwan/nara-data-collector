## 실제 MCP SDK 상호운용

별도 검증에서 공식 Python MCP SDK 1.27.0 클라이언트와 이 제품 서버 사이 stdio를 연결했습니다. 2025-11-25 초기화, 다섯 도구 목록 및 각 도구 호출을 확인했습니다. coverage 성공, 키 없는 search/detail은 null+missing_api_key, collect/status는 blocked 작업 저장과 재조회로 확인했으며 외부 API 호출은 0회입니다.

증거 ID: `owned-mcp-sdk-20261024T081333.707208Z-39331342`. 클라이언트 시험에만 이미 설치된 SDK를 사용했습니다. 서버 런타임은 제품 자체 환경과 src입니다. SDK가 이 제품의 설치 의존성이라는 뜻은 아니며, 새 ZIP의 독립 설치 시험과는 별개입니다.

## 발견과 수정

- 계약번호만으로 중복 제거하면 변경차수나 참가업체를 잃을 수 있어 전체 원문 기준 중복 제거로 바꾸고 회귀시험을 추가했습니다.
- 필터 후 0행인 페이지의 fingerprint만 비교하면 잘못된 반복 판정을 만들 수 있어 필터 전 원문의 fingerprint로 검사합니다. 같은 페이지가 반복되면 필터 여부와 관계없이 실패합니다.
- 최종 페이지가 원천 총수보다 많은 행을 반환하거나 응답 페이지 크기가 요청과 다르면 실패하도록 검증을 추가했습니다.
- 상태 조회는 명시적 읽기 트랜잭션으로 checkpoint·행수·원문을 같은 SQLite 스냅샷에서 읽습니다. 조회 도중 별도 writer가 커밋하는 회귀시험으로 구상태/신행수 혼합 방지를 확인했습니다.
- 초기화되지 않은 DB의 상태 조회를 null+uninitialized_or_invalid_job_state로 처리합니다.
- 시스템 Python의 ensurepip 부재를 확인하여 기존 uv가 있으면 해당 도구로 독립 환경을 만드는 경로를 추가했습니다. 전역 패키지는 변경하지 않습니다.
- 발주계획의 Swagger required 필드만으로 조건을 판단하지 않고 공식 참고 DOCX의 발주년월·게시기간 조건부 필수 항목을 반영했습니다.

API 원천 데이터가 수집 중 바뀌는 상황에 완전한 스냅샷을 제공하지 않습니다. 검증한 것은 고정된 가상 원천에서 저장 중단·재개로 누락과 중복을 만들지 않는 동작 및 명시된 네 개 실API의 부분 응답입니다.
